'''崩溃（Crash）'''是程序因未预期的异常而停止正常流程进行的应急性处理，而'''崩溃报告（Crash Report）'''是用于描述这次崩溃具体信息的报告。

== 分类 ==
在游戏中，崩溃报告分为几个种类。按照崩溃是否会影响程序进程，崩溃分为两类：
* 非致命崩溃：崩溃虽然发生，但游戏不至于因为这次崩溃而停止所有游戏流程，因此此类崩溃虽然有崩溃报告但不会引发程序中止。
* 致命崩溃：崩溃发生后，游戏无法阻止崩溃的影响，使得所有游戏流程停止。崩溃报告可能产生，程序在之后会被立刻中止。

按照崩溃发生的位置，崩溃被分为下列6种：
* 常规崩溃：致命崩溃，游戏在保存常规崩溃报告后会立刻中止进程。这类崩溃产生于游戏的各个流程中，当游戏没有捕获并正常处理异常时，常规崩溃就会产生以阻止程序继续错误运行。
* 测试崩溃：非致命崩溃，用于性能分析报告。
* 网络协议崩溃：非致命崩溃，在连接远程服务端时，如果服务端因为网络协议问题而中止连接，就会在客户端触发网络协议崩溃。
* 区块文件崩溃：非致命崩溃，游戏在保存或读取区块时，如果区块内部数据异常造成程序异常，游戏就会产生区块文件崩溃。
* JVM崩溃：致命崩溃，但此崩溃无法产生游戏崩溃报告，也无法应急保存数据。这种崩溃生成JVM崩溃报告。
* 外部崩溃：致命崩溃，由外部引发，例如强制停止进程（发送SIGKILL信号等方式）、因内存占用过高而被[https://www.kernel.org/doc/html/latest/admin-guide/mm/concepts.html?highlight=oom+killer#oom-killer OOM Killer]杀死进程等。这类崩溃无法生成任何崩溃报告，因为生成报告之前程序就已经中止。

== 存储路径 ==
按照崩溃的不同，游戏保存崩溃报告文件的路径也不同：
* 常规崩溃报告保存在{{filepath|-{}-<''游戏根目录''>/crash-reports/crash-<''时间''>-<''逻辑端类型''>.txt}}。
* 测试崩溃报告保存在[[性能分析报告文件]]内部的指定位置。
* 网络协议崩溃报告保存在{{filepath|-{}-<''客户端根目录''>/crash-reports/disconnect-<''时间''>-client.txt}}。
* 区块文件崩溃报告保存在{{filepath|-{}-<''游戏根目录''>/crash-reports/chunk-<''维度名称''>-<''时间''>-server.txt}}。
* JVM崩溃报告保存在{{filepath|-{}-<''运行目录''>/hs_err_pid<''进程ID''>.log}}。

== 文件结构 ==
所有游戏崩溃报告都有统一的结构，分为头部和各个章节信息。

=== 文件头部 ===

文件头部具有下列结构：

<pre>-{}-
---- <报告类型> ----
// <诙谐评论>

Time: <崩溃时间>
Description: <崩溃简要描述>

<异常描述及栈帧信息>
</pre>

=== 信息章节 ===
文件头部粗略说明了异常的发生位置与原因，在文件头部下方，游戏会附加一些更详细的信息以帮助分析崩溃。

为了将信息章节与文件头部分隔，崩溃报告中使用下列这两行用于分隔开文件头部和信息章节：

<pre>
A detailed walkthrough of the error, its code path and all known details is as follows:
---------------------------------------------------------------------------------------
</pre>

每个信息章节都有下列的结构：

<pre>-{}-
-- <信息类型> --
Details:
	<数据描述>: <数据值>
    ...
Stacktrace:
	<生成此章节的栈帧信息>
</pre>

其中，<code>Stacktrace</code>部分可能不存在，具体和信息类型有关。<code>Details</code>内的数据与信息类型相关，指定的信息类型会提供相应的数据。

如果在生成崩溃报告时，数据值为空，那么数据值会变为<code>~~NULL~~</code>；如果数据值获取发生异常，则为<code>-{}-~~ERROR~~ <''异常类型名''>: <''异常描述''></code>。

=== 常见信息类型 ===
下列举例了崩溃报告中经常出现的信息类型。

==== Head ====
<code>Head</code>是特殊的信息类型，永远作为崩溃报告的第一个章节。且固定格式为：

<pre>-{}-
-- Head --
Thread: <当前线程名称>
Stacktrace:
	<与头部相同的栈帧信息>
</pre>

==== System Details ====
包含了操作系统、硬件及游戏本体信息，不包含栈帧信息。所有崩溃报告都有这一章节，且一定作为最后一个章节写入崩溃报告。

此章节包含下列数据，部分数据可能不会最终保存在崩溃报告中：
* '''Minecraft Version'''：游戏版本名称。
* '''Minecraft Version ID'''：游戏版本ID。
* '''Operating System'''：操作系统。此值本质上读取Java系统属性的{{cd|os.name|os.arch|os.version|d=pretty}}，并拼接而成。
* '''Java Version'''：Java运行时信息。此值本质上读取Java系统属性的{{cd|java.version|java.vendor|d=pretty}}，并拼接而成。
* '''Java VM Version'''：Java虚拟机信息。此值本质上读取Java系统属性的{{cd|java.vm.name|java.vm.info|java.vm.vendor|d=pretty}}，并拼接而成。
* '''Memory'''：内存使用情况。内部的3个内存数据指标分别是[https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/Runtime.html#freeMemory() Java堆内空闲内存]、[https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/Runtime.html#totalMemory() Java堆内存]和[https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/Runtime.html#maxMemory() Java最大堆内存]。
* '''CPUs'''：Java虚拟机可用的处理器数量，见[https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/Runtime.html#availableProcessors() 此文档]。
* '''Processor Vendor'''：处理器供应商，见[https://www.oshi.ooo/oshi-core/apidocs/oshi/hardware/CentralProcessor.ProcessorIdentifier.html#getVendor() 此文档]。
* '''Processor Name'''：处理器名称，见[https://www.oshi.ooo/oshi-core/apidocs/oshi/hardware/CentralProcessor.ProcessorIdentifier.html#getName() 此文档]。
* '''Identifier'''：处理器标识符，见[https://www.oshi.ooo/oshi-core/apidocs/oshi/hardware/CentralProcessor.ProcessorIdentifier.html#getIdentifier() 此文档]。
* '''Microarchitecture'''：处理器微架构，见[https://www.oshi.ooo/oshi-core/apidocs/oshi/hardware/CentralProcessor.ProcessorIdentifier.html#getMicroarchitecture() 此文档]。
* '''Frequency (GHz)'''：处理器频率，见[https://www.oshi.ooo/oshi-core/apidocs/oshi/hardware/CentralProcessor.ProcessorIdentifier.html#getVendorFreq() 此文档]。	
* '''Number of physical packages'''：物理封装数量，见[https://www.oshi.ooo/oshi-core/apidocs/oshi/hardware/CentralProcessor.html#getPhysicalPackageCount() 此文档]。
* '''Number of physical CPUs'''：物理处理器数量，见[https://www.oshi.ooo/oshi-core/apidocs/oshi/hardware/CentralProcessor.html#getPhysicalProcessorCount() 此文档]。
* '''Number of logical CPUs'''：逻辑处理器数量，见[https://www.oshi.ooo/oshi-core/apidocs/oshi/hardware/CentralProcessor.html#getLogicalProcessorCount() 此文档]。
* '''Graphics card #<''序号''> name'''：显卡名称，见[https://www.oshi.ooo/oshi-core/apidocs/oshi/hardware/GraphicsCard.html#getName() 此文档]。
* '''Graphics card #<''序号''> vendor'''：显卡供应商，见[https://www.oshi.ooo/oshi-core/apidocs/oshi/hardware/GraphicsCard.html#getVendor() 此文档]。
* '''Graphics card #<''序号''> VRAM (MiB)'''：显存大小，以兆字节（MiB）为单位，见[https://www.oshi.ooo/oshi-core/apidocs/oshi/hardware/GraphicsCard.html#getVRam() 此文档]。
* '''Graphics card #<''序号''> deviceId'''：显卡硬件ID，见[https://www.oshi.ooo/oshi-core/apidocs/oshi/hardware/GraphicsCard.html#getDeviceId() 此文档]。
* '''Graphics card #<''序号''> versionInfo'''：显卡更详细的版本信息数据，见[https://www.oshi.ooo/oshi-core/apidocs/oshi/hardware/GraphicsCard.html#getVersionInfo() 此文档]。
* '''Memory slot #<''序号''> capacity (MiB)'''：物理内存的大小，以兆字节（MiB）为单位，见[https://www.oshi.ooo/oshi-core/apidocs/oshi/hardware/PhysicalMemory.html#getCapacity() 此文档]。
* '''Memory slot #<''序号''> clockSpeed (GHz)'''：物理内存的时钟周期，以吉赫兹（GHz）为单位，见[https://www.oshi.ooo/oshi-core/apidocs/oshi/hardware/PhysicalMemory.html#getClockSpeed() 此文档]。
* '''Memory slot #<''序号''> type'''：物理内存的类型，见[https://www.oshi.ooo/oshi-core/apidocs/oshi/hardware/PhysicalMemory.html#getMemoryType() 此文档]。
* '''Virtual memory max (MiB)'''：设备总内存，以兆字节（MiB）为单位，见[https://www.oshi.ooo/oshi-core/apidocs/oshi/hardware/VirtualMemory.html#getVirtualMax() 此文档]。
* '''Virtual memory used (MiB)'''：设备已用内存，以兆字节（MiB）为单位，见[https://www.oshi.ooo/oshi-core/apidocs/oshi/hardware/VirtualMemory.html#getVirtualInUse() 此文档]。
* '''Swap memory max (MiB)'''：交换空间总大小，以兆字节（MiB）为单位，见[https://www.oshi.ooo/oshi-core/apidocs/oshi/hardware/VirtualMemory.html#getSwapTotal() 此文档]。
* '''Swap memory used (MiB)'''：交换空间已用大小，以兆字节（MiB）为单位，见[https://www.oshi.ooo/oshi-core/apidocs/oshi/hardware/VirtualMemory.html#getSwapUsed() 此文档]。
* '''Space in storage for jna.tmpdir (MiB)'''：JNA临时目录（系统属性<code>jna.tmpdir</code>）所在文件系统的可用空间和已用空间，以兆字节（MiB）为单位。
* '''Space in storage for org.lwjgl.system.SharedLibraryExtractPath (MiB)'''：LWJGL本地库目录（系统属性<code>org.lwjgl.system.SharedLibraryExtractPath</code>）所在文件系统的可用空间和已用空间，以兆字节（MiB）为单位。
* '''Space in storage for io.netty.native.workdir (MiB)'''：Netty本地库工作目录（系统属性<code>io.netty.native.workdir</code>）所在文件系统的可用空间和已用空间，以兆字节（MiB）为单位。
* '''Space in storage for java.io.tmpdir (MiB)'''：Java临时目录（系统属性<code>java.io.tmpdir</code>）所在文件系统的可用空间和已用空间，以兆字节（MiB）为单位。
* '''Space in storage for workdir (MiB)'''：当前工作目录所在文件系统的可用空间和已用空间，以兆字节（MiB）为单位。
* '''JVM Flags'''：Java虚拟机旗标。
* '''Is Modded'''：游戏本体是否已被修改。下文的游戏铭牌代表游戏中<code>net.minecraft.client.ClientBrandRetriever#getClientModName()</code>（客户端）和<code>net.minecraft.server.MinecraftServer#getServerModName()</code>（服务端）的返回值。
** 如果游戏本体未被修改（游戏铭牌为<code>vanilla</code>，且游戏本体文件具有有效签名），则为<code>-{}-Probably not. <''逻辑端类型''> jar signature and brand is untouched</code>。
** 如果游戏铭牌未被修改，但游戏本体文件没有有效签名，则为<code>-{}-Very likely; <''逻辑端类型''> jar signature invalidated</code>。
** 如果游戏铭牌被修改，则为<code>-{}-Definitely; <''逻辑端类型''> brand changed to '<''游戏铭牌''>'</code>。
* '''Type'''：崩溃发生线程所代表的逻辑端详细类型。
** 如果游戏在客户端渲染线程崩溃，则为<code>Client (map_client.txt)</code>。
** 如果游戏在客户端内置服务端线程崩溃，则为<code>Integrated Server (map_client.txt)</code>。
** 如果游戏是专用服务端，并发生崩溃，则为<code>Dedicated Server (map_server.txt)</code>。

下列其他数据仅在客户端中存在，服务端生成崩溃报告将不会产生下列数据：
* '''Launched Version'''：游戏版本，此项由外部使用<code>--version</code>参数传入。
* '''Launcher name'''：游戏启动器名称，此项由外部使用<code>minecraft.launcher.brand</code>系统属性传入。如果对应系统属性不存在则此项也不存在。
* '''Backend library'''：LWJGL运行库信息。
* '''Backend API'''：OpenGL渲染器信息。此值本质上读取了{{cd|GL_RENDERER|GL_VERSION|GL_VENDOR|d=pretty}}三个OpenGL常量代表的字符串。如果游戏没有创建或不存在OpenGL上下文时崩溃，则此值为<code>NO CONTEXT</code>。
* '''Window size'''：游戏窗口大小。如果游戏还没有完成初始化时就已经崩溃，那么此值为<code><not initialized></code>。
* '''GFLW Platform'''{{sic}}：GLFW的运行平台，见[https://www.glfw.org/docs/latest/group__init.html#ga6d6a983d38bd4e8fd786d7a9061d399e 此文档]。
* '''GL Caps'''：固定值为<code>Using framebuffer using OpenGL 3.2</code>。
* '''GL debug messages'''：输出OpenGL最后10条调试信息。如果OpenGL上下文不支持[https://registry.khronos.org/OpenGL/extensions/KHR/KHR_debug.txt GL_KHR_debug]和[https://registry.khronos.org/OpenGL/extensions/ARB/ARB_debug_output.txt GL_ARB_debug_output]扩展，则此值为<code><debugging unavailable></code>。如果游戏无法找到渲染设备，则为<code><no renderer available></code>。
* '''Universe'''：如果游戏未初始化就已经崩溃，此值为<code>404</code>，否则为<code>400921fb54442d18</code>（Java标准库常数圆周率<code>Math.PI</code>转换为对应长整数的16进制表示）。
* '''GPU Warnings'''：GPU警告，与资源包内定义的[[资源包#GPU警告列表|GPU警告列表]]有关。如果选项还未初始化，此值不存在。
* '''Graphics mode'''：图像品质，与选项中的<code>graphicsMode</code>一致。如果选项还未初始化，此值不存在。
* '''Render Distance'''：视距，与选项中的<code>renderDistance</code>一致。如果选项还未初始化，此值不存在。
* '''Resource Packs'''：游戏已启用的资源包。如果游戏还未初始化，此值不存在。
* '''Current Language'''：游戏使用的语言。如果语言还未初始化，此值不存在。
* '''Locale'''：系统的区域设置，见[https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/util/Locale.html#getDefault() 此文档]。
* '''System encoding'''：系统编码。此值本质读取系统属性<code>sun.jnu.encoding</code>。如果对应系统属性不存在则为<code><not set></code>。
* '''File encoding'''：文件编码。此值本质读取系统属性<code>file.encoding</code>。如果对应系统属性不存在则为<code><not set></code>。
* '''CPU'''：处理器信息，是上述处理器信息的拼接。

==== Manual crash details ====
当使用{{key|F3+C}}时客户端崩溃时，崩溃报告中包含此章节，且具有栈帧信息。

内部仅包含一条数据<code>Modules</code>，保存了游戏使用的所有本地模块（动态链接库）。只有在Windows系统下数据不为空，其他系统则为空。每一行都代表了一个模块，且格式为<code>-{}-<''模块路径''>:<''模块描述''>:<''模块版本''>:<''模块提供者''></code>。

此数据本质上调用了<code>Kernel32Util.getModules</code>，文档见[http://java-native-access.github.io/jna/5.13.0/javadoc/com/sun/jna/platform/win32/Kernel32Util.html#getModules-int- 此]。
