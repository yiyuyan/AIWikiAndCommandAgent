[[区块]]以16×16的水平范围为单位存储地形等信息。区块也会同时储存预先计算好的光照、[[高度图]]数据及其他数据信息，以加快游戏处理。 

== 存储格式 ==

区块存储文件是一种区块数据，以[[区域文件格式]]为载体，存储于{{filepath|-{}-<''维度根目录''>/region}}内。例如，主世界的区块存储文件全部位于{{filepath|-{}-<''存档根目录''>/dimensions/minecraft/overworld/region}}，下界的全部位于{{filepath|-{}-<''存档根目录''>/dimensions/minecraft/the_nether/region}}。

区块数据有下列存储格式：

** {{nbt|compound|below_zero_retrogen}}：用于在升级为1.18的世界时，原区块负值高度重新生成方块的数据。此项只对于原型区块有效，如果此区块已经达到<code>full</code>（区块生成完毕）阶段成为世界区块时，此标签被删除。
*** {{nbt|long-array|missing_bedrock}}：每个二进制位代表对应位置上是否缺失[[基岩]]，决定是否重新生成此位置下的方块。一共256个二进制位（4个长整型整数），位置编码从(0,0)开始横向扫描到(15,15)结束。此项不存在则代表基岩全部存在。

** {{nbt|bool|shouldSave}}：（无法导出，仅能通过修改区块数据设置）表示在加载区块后是否要标记此区块已被修改，从而在服务器下次自动保存时可以将区块数据强制写入到文件内。

**** {{nbt|compound}}：一个流体计划刻。
***** 见{{slink||计划刻存储格式}}。
*** {{nbt|byte|Sides|existonsave=1|required=1}}：其中的二进制位表示是否对某一方向上的区块进行更新升级，从低位到高位分别表示北、东北、东、东南、南、西南、西、西北。

== 方块位置编码 ==

在区块存储格式中有多处使用到了位置编码。在一个子区块内，因为位置有限，所以实际上有效的位置很少，可以将这个数字压缩到一个整数内而不需要同时保存XYZ坐标。

在每个子区块内，XYZ三个坐标的值域都是0到15，共16个数字，可以使用4个二进制位编码，组合起来一个编码只需要12个二进制位，共4096个值。而根据XYZ三个坐标在数字二进制位内的不同排序方式，方块位置编码分为两种：'''YZX编码'''和'''ZYX编码'''，二者的区别在于Y坐标和Z坐标的二进制位位置不同。下列算法给出了两种编码的转换方式，其中输入是子区块内方块坐标。

<syntaxhighlight lang="java">
public static int toYZX(int x, int y, int z) {
	return y << 8 | z << 4 | x;
}

public static int toZYX(int x, int y, int z) {
	return z << 8 | y << 4 | x;
}
</syntaxhighlight>

在{{nbt|compound|CarvingMasks}}中还存在一种按照区块计算的方块位置编码。其中XZ坐标都是0-15，但是Y是'''从建筑最低高度开始计算'''的，也就是Y不会产生负数，且最大不会超过4096。游戏也按照YZX的顺序将它编入一个数字内，下列代码中XYZ是世界位置，<code>dimensionMinY</code>是当前维度最低建筑高度：

<syntaxhighlight lang="java">
public static int toExtendedYZX(int x, int y, int z, int dimensionMinY) {
	return (y - dimensionMinY << 8) | (z & 0xF << 4) | (x & 0xF);
}
</syntaxhighlight>

== 调色板存储格式 ==

为实现数据压缩，游戏对生物群系和方块的存储上引入了'''调色板'''（'''Palette'''）机制。下方描述中，调色板存储的对象（生物群系或方块状态）被称为元素。

如果子区块内只有一种元素，那么游戏只需要声明这一种元素就可以代表这整个子区块内都是这个元素。在这种情况下，调色板内只有{{nbt|list|palette}}标签，且内部只有一个数据记录这唯一的元素。

如果子区块内不止一种元素，游戏会根据元素数量''c''，计算存储位数''b''：
* 如果调色板用于存储方块状态：
** 当''c''为1-16时，''b''为4。
** 当''c''大于16时，''b''为<math>\lceil \log_2{c} \rceil</math>。
* 如果调色板用于存储生物群系，则<math>b=\lceil \log_2{c} \rceil</math>。

游戏将这些元素从0编号，产生一个映射，保存到{{nbt|list|palette}}标签中，而数据则存储到{{nbt|long-array|data}}中。

根据存储位数''b''，推算一个长整数（64位整数）能存储多少个元素<math>u=\lfloor 64/b \rfloor</math>。例如，如果一个子区块内部有6种方块状态，那么存储位数''b''是4，长整数能存储元素的数量''u''是16，根据子区块内方块位置数量4096可以得知一共需要256个长整数才能存储整个子区块数据；再例如，如果子区块内有7种生物群系，那么存储位数''b''是3，长整数能存储元素的数量''u''是21，根据子区块内生物群系单元数量64可以得知需要4个长整数才能保存整个子区块数据。

元素写入排序与方块位置编码类似：
* 对于方块状态，子区块内坐标XYZ范围是0-15，编码后序号''i''为<math>256y+16z+x</math>，与YZX编码一致。
* 对于生物群系单元，子区块坐标XYZ范围是0-3，编码后序号''i''为<math>16y+4z+x</math>。

每个元素，按照序号从长整数的低位填充到高位，填充一个长整数后直接从下一个长整数的最低位开始填充，而不会横跨两个长整数填充。

下方代码给出了使用序号''i''，读取存储位数为''b''（长整数能存储元素的数量为''u''）调色板数据：

<syntaxhighlight lang="java">
public int getPalette(int i) {
	return (int) (data[i / u] >> (i % u)) & ((1L << b) - 1L);
}
</syntaxhighlight>

== 高度图存储格式 ==

高度图使用了类似调色板的存储方式，也使用一个长整数数组保存数据：
* 游戏需要计算存储位数''b''。假设此维度的整体高度（最低建筑高度到最高建筑高度之差）为''h''，则<math>b=\lceil \log_2{h} \rceil</math>。
* 根据存储位数''b''，推算一个长整数（64位整数）能存储多少个元素<math>u=\lfloor 64/b \rfloor</math>。
* 推算长整数数组长度<math>l=\lceil 256/u \rceil</math>。

由于高度图中只有XZ坐标（子区块内），所以编码序号算法也发生了改变：编码后序号''i''为<math>x+16z</math>。下方代码给出了坐标为(x, z)、维度最低建筑高度为''low''、最高建筑高度为''high''获取高度数据的算法：

<syntaxhighlight lang="java">
public static long getHeightmap(int x, int z, long low, long high) {
	int b = Mth.ceillog2(high - low); // 计算对2的对数后向上取整
    int u = 64 / b;
    int i = x + 16 * z;
	return (data[i / u] >> (i % u)) & ((1L << b) - 1L) + low;
}
</syntaxhighlight>

== 亮度存储格式 ==

亮度存储格式也使用了数组，但是是字节数组。因为亮度是0-15，只需要4个比特，而1个字节是8比特，所以每个字节存储两个亮度信息，整个子区块内4096个亮度信息共2048字节。

写入顺序按照YZX编码。

<syntaxhighlight lang="java">
public static int getLight(int x, int y, int z) {
	int yzx = toYZX(x, y, z);
    return (data[yzx >> 1] >> (4 * (yzx & 1))) & 0xF;
}
</syntaxhighlight>

== 计划刻存储格式 ==

计划刻是游戏“预计在某个时间点要进行的行为”，它需要保存要更新的位置、更新的优先级和要更新的时间。

<div class="treeview">
* {{nbt|compound}} 计划刻数据
** {{nbt|string|i|existonsave=1|required=1}}：（命名空间ID）计划刻被申请时，此方块位置上的方块或流体。如果在计划刻执行时方块位置上的方块或流体发生了变化，则不直接忽略此计划刻。
** {{nbt|int|p|existonsave=1|required=1}}：计划刻的处理优先级。如果多个计划刻被安排入同一游戏刻中，那么优先级值较小的计划刻会被优先处理。一共有7个优先级：-3（最高优先级，只用于红石比较器和红石中继器）、-2（极高优先级，只用于红石比较器和红石中继器）、-1（高优先级，只用于红石比较器和红石中继器）、0（普通优先级）、1（低优先级，没有任何方块使用）、2（极低优先级，没有任何方块使用）、3（最低优先级，没有任何方块使用）。
** {{nbt|int|t|existonsave=1|required=1}}：距离此计划刻将要执行的倒计时，以游戏刻为单位。
** {{nbt|int|x|existonsave=1|required=1}}：X坐标。如果此坐标在指定区块外则此计划刻数据无效。
** {{nbt|int|y|existonsave=1|required=1}}：Y坐标。
