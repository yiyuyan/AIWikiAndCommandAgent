Minecraft使用'''无效纹理'''与'''无效模型'''以应对存在于游戏资源与[[资源包]]的潜在错误。

== 无效纹理 ==
[[File:Missing Texture.png|right|150px|class=pixel-image]]
'''无效纹理'''，或'''丢失的纹理（Missing Texture）'''是一种特殊的[[纹理]]，它由游戏自动生成，自动添加到所有纹理图集中，并使用<code>minecraft:missingno</code>作为映射命名空间ID。同时，无效纹理也可以作为一个独立纹理，也使用<code>minecraft:missingno</code>作为此纹理的命名空间ID。

无效纹理的尺寸固定为16×16，不随纹理图集大小而改变。其纹理呈棋盘状，由黑色（{{Color|#000000}}）与品红色（{{only|je|for={{Color|#F800F8}}}}或{{only|be|for={{Color|#FC00FF}}}}）组成，以在大多数情况下尽可能地显眼。类似的纹理也被其他游戏工作室使用。<ref>如[https://developer.valvesoftware.com/wiki/Missing_content Valve]。</ref>

当游戏找不到指定的纹理时，游戏会自动将请求的命名空间ID引用到无效纹理，替代缺失的纹理。若指定的纹理的元数据加载产生错误，游戏也会使用无效纹理替代发生错误的纹理。

游戏使用了无效纹理后，会在游戏的输出日志中生成报告：
* 找不到纹理图集内的指定纹理时生成<code>|Using missing texture, unable to load [NAMESPACE]:textures/[TEXTURE].png : java.io.FileNotFoundException: [NAMESPACE]:textures/[TEXTURE].png</code>
* 模型元素缺少对应的纹理时生成<code>Unable to resolve texture reference: #texture in [NAMESPACE]:block/[MODEL]</code>

原版游戏也可以出现无效纹理，然而需要使用命令，游戏加载这些无效纹理时也不一定会在输出日志产生警告：{{more info|1.21.9后}}<!--more are added in 1.21.9, see en: page-->

* 指定粒子使用空气粒子。
** 将[[空气]]、[[洞穴空气]]或[[虚空空气]]应用于<code>minecraft:block_marker</code>粒子：<ref>{{bug|MC-239407|||WAI}}</ref>
*** {{cmd|particle minecraft:block_marker{block_state: "minecraft:air"}<nowiki/>}}
** 将空气的物品模型应用于物品，并使物品产生粒子：
*** {{cmd|particle minecraft:item{item: {id: "minecraft:cookie", components: {"minecraft:item_model": "minecraft:air"}<nowiki/>}<nowiki/>}<nowiki/>}}
* 指定不存在的资源路径，使游戏直接或间接调用无效纹理。
** 无效的提示框纹理：<ref>{{bug|MC-276751|||Won't Fix}}</ref>
*** {{cmd|give @s stick[minecraft:tooltip_style{{=}}"minecraft:missingno"]}}
** 无效的装备模型：<ref>{{bug|MC-276772|||Won't Fix}}</ref>
*** {{cmd|give @s stick[equippable{{=}}{slot:"chest",asset_id:"minecraft:missingno"}]}}
** 无效的装备遮罩层：
*** {{cmd|give @s stick[equippable{{=}}{slot:"chest",camera_overlay:"minecraft:missingno"}]}}
** 无效的路径点样式：
*** {{cmd|waypoint modify @s style set minecraft:missingno}}

== 无效模型 ==
{{about|异常方块模型的占位符||占位符方块|section=1}}
[[File:Missing Model.png|right|150px]]
'''无效模型'''，或'''丢失的模型（Missing Model）'''是一类特殊的[[模型]]。如果游戏没有找到模型，或在模型加载中产生了错误，游戏会自动将异常的模型替换为无效模型。

无效模型的命名空间ID是<code>builtin/missing</code>，它的外观是一个6面纹理都是无效纹理的方块。其硬编码模型可以导出为：

<syntaxhighlight lang="json">
{
  "textures": {
    "particle":  "missingno",
    "missingno": "missingno"
  },
  "elements": [
    {
      "from": [ 0,  0,  0],
      "to":   [16, 16, 16],
      "faces": {
        "down":  { "texture": "#missingno", "uv": [0, 0, 16, 16], "cullface": "down"  },
        "up":    { "texture": "#missingno", "uv": [0, 0, 16, 16], "cullface": "up"    },
        "north": { "texture": "#missingno", "uv": [0, 0, 16, 16], "cullface": "north" },
        "south": { "texture": "#missingno", "uv": [0, 0, 16, 16], "cullface": "south" },
        "west":  { "texture": "#missingno", "uv": [0, 0, 16, 16], "cullface": "west"  },
        "east":  { "texture": "#missingno", "uv": [0, 0, 16, 16], "cullface": "east"  }
      }
    }
  ]
}
</syntaxhighlight>

以下情况不使用无效模型：
* 所有[[模型#动态模型|动态模型]]。这些模型被硬编码，无法通过资源包修改。
* 被硬编码为隐形的方块：
** {{BlockLink|Air}}
** {{BlockLink|Cave Air}}
** {{BlockLink|Void Air}}
** {{BlockLink|Barrier}}
** {{BlockLink|Light}}
** {{BlockLink|Structure Void}}

原版游戏也可以出现无效模型，然而需要使用命令，游戏加载无效模型时也不一定会在输出日志产生警告：

* 指定不存在的模型映射，使游戏间接调用无效模型。
** 无效的物品模型映射：<ref>{{bug|MC-276671|||WAI}}</ref>
*** {{cmd|give @s stone[item_model{{=}}"minecraft:missingno"]}}
