'''区块（Chunk）'''是Minecraft世界里一个大小为16×16的区域。

== 生成 ==
新建世界时会在出生点附近生成区块，默认情况下，世界中最初会生成{{only|je|for=29×29}}或{{only|be|for=45×45}}个区块。{{in|je}}[[世界加载屏幕]]上会显示世界的生成和加载进度。随着玩家对世界的探索，相邻的区块也会被生成。

区块是通过[[种子（世界生成）|種子碼]]进行生成的，这意味着在相同的版本下，使用相同的種子碼，生成的区块也会基本相同。

== 区块位置与范围 ==
{{Filetr|Minecraft axes.svg|thumb|以俯视的视角展示了X和Z轴的图像。红色高亮表示与标准不同的轴}}
区块宽16格，长16格，且水平方向上与16整数倍的位置对齐。在[[主世界]]中，区块高384格；在[[下界]]中，区块高{{only|je|for=256格}}或{{only|be|for=128格}}；而在[[末地]]中，区块高256格。

区块还可以再细分为'''子区块'''（'''Sub Chunk'''/'''Chunk Section'''）。子区块高16格，且顶底坐标均为16的整数倍。

{{in|be}}由于(0, 0)算作一格，且屬於東南（正數）方向，所以(0, 0)到(15, 15)是一個區塊，而(-1, -1)到(-16, -16)是另一個區塊。在計算區塊時，東南（正數）方向為16的整数倍最後減一次1（(0, 0)是一格），而西北（負數）方向為16的整数倍但無需最後減一次1，例如正數0到15共16格，負數-1到-16共16格。区块的西北角XZ坐标总是16的整数倍。

方块位置可以通过简单的计算转换为对应区块的位置：将方块位置除以16，并向下取整，得到的XZ坐标就是区块位置，而XYZ综合起来的坐标就是子区块位置。用代码可以表示如下：

<syntaxhighlight lang="java">
int chunkX = blockX >> 4;
int chunkZ = blockZ >> 4;
int subChunkY = blockY >> 4;
</syntaxhighlight>

{{in|je}}区块和子区块的范围可以使用{{key|F3+G}}查看：蓝色的线勾勒出每个子区块的范围，红色的线标明了附近几个区块的边界。在[[调试屏幕]]中，“Chunk”行也说明了当前所在的子区块位置。

== 区块加载 ==
由于一个世界极大并且包含极多区块，因此游戏仅加载部分区块以使游戏能够稳定运行。游戏不会运算已卸载的区块。

=== Java版 ===
; 加载等级{{anchor|加载等级}}
'''加载等级'''用于决定这个区块是否能被加载和区块生成的程度，取决于[[渲染距离]]。加载等级的范围是0-45，加载等级大于44的区块会被立刻卸载。

加载等级可以分为以下四种加载等级类型：

; 计算等级{{anchor|计算等级}}
类似于加载等级，'''计算等级'''决定了这个区块应该计算什么内容，取决于[[模拟距离]]，它的范围是0-33。

计算等级和加载等级一起决定了区块能否计算实体和方块等内容。如果一个区块加载等级为实体计算加载等级（小于等于31）且计算等级也小于等于31，则区块内的实体、方块实体和计划刻每游戏刻都进行各种计算，这种类型的区块通常被称为'''强加载区块（Entity Processing Chunk）'''；如果一个区块加载等级为实体计算加载等级或方块计算加载等级（小于等于32）且计算等级等于32，则区块内的方块实体和计划刻会被计算，实体会被追踪和记录，但无法参加每游戏刻的计算，这种类型的区块通常被称为'''弱加载区块（Lazy Processing Chunk）'''。如果一个区块加载等级是完全加载等级（33）且计算等级等于32，则区块内实体会被追踪和记录，但计划刻和方块实体无法参加每游戏刻的计算，这种类型的区块通常被称为'''加载边界区块（Loading Border Chunk）'''。计算等级等于33或加载等级大于33代表区块内实体、方块实体和计划刻不会被计算。

当实体和方块事件穿过不同加载行为的区块时，会产生多种特殊情况：
* 尝试移动到弱加载或加载边界区块的实体在离开强加载区块后会即刻停止所有活动。当这个区块变为强加载区块时，实体会按照进入时的位置和速度继续移动。
* 加载边界区块中的方块可以请求一个计划刻，但是直到该区块变为强加载或弱加载区块时才进行处理。
* 强加载区块中的点燃的[[TNT]]可以摧毁弱加载和加载边界区块内的方块。
* 流动的[[水]]、[[熔岩]]和[[火]]可以扩散到加载边界区块的第一个相邻方块，但流动会暂停，直到外部区块变为强加载或弱加载区块。
* 在强加载区块边缘生长的南瓜和西瓜茎可将其果实放置在外面区块的相邻方块上。

; 出生点标签
寻找玩家出生点或[[世界出生点]]时，会在所搜索的区块放置基础等级为33的加载标签，存活时间为{{convert|1}}。

; 末影龙标签
当有玩家参加[[末影龙]]战斗时，系统自动在末地的(0,0)区块放置基础等级为24的加载标签和计算标签。当所有玩家都退出末影龙战斗或末影龙战斗结束，此标签自动释放。

;加入世界标签
玩家加入世界期间，玩家预期位置所在区块会获得基础等级为30的加载标签，存活时间为{{convert|20}}。服务端生成玩家期间，为了保持区块加载，此标签每刻不断放置。

;玩家标签
每个玩家都会在以自身所在区块放置一个基础等级为<math>\max\{0, 31-s\}</math>的计算标签，其中''s''是模拟距离。

同时，每个玩家以自身区块为中心的一个正方形范围内放置基础等级为31的加载标签。放置加载标签的范围只与客户端或服务器的渲染距离有关：在单人游戏中，正方形的边长为<math>2d+1</math>，其中''d''是客户端的[[渲染距离]]；在多人游戏中，正方形边长的公式不变，但''d''为[[server.properties]]中的<code>view-distance</code>的值。

当渲染距离发生变化时，玩家加载标签的范围也会随之改变；当模拟距离发生变化时，玩家计算标签的等级也会随之改变。

拥有玩家计算标签的区块会使维度计算保持活跃。

; 强制加载标签
使用{{cmd|forceload}}可使得区块获得基础等级为31的加载标签和计算标签。与出生点加载标签类似，它只取决于当前世界的数据，在游戏重启后这些标签依旧有效。

拥有此标签的区块会使维度计算保持活跃。

; 传送门标签
实体穿过[[下界传送门]]或进出末地后，在目标维度的目标区块放置基础等级为30的加载标签和计算标签，存活时间为{{convert|300}}。传送门加载标签是为了实体跨越维度后能在目标位置上可以继续被计算，而存活时间保证了在跨越维度后目标位置不会一直被加载。

拥有此标签的区块会使维度计算保持活跃。

; 末影珍珠标签
如果一个[[末影珍珠]]由玩家掷出，那么这个末影珍珠就会和玩家绑定。与玩家绑定的末影珍珠所在区块会获得一个基础加载等级为31的加载标签和计算标签，存活时间为{{convert|40}}。末影珍珠利用这个标签维持自身的运动。末影珍珠每{{convert|39}}会强制为区块添加标签，如果末影珍珠因为运动而进入另一个区块，那么也会对新的区块立刻添加标签，无视上述计时器影响，以保证在运动路径上可以被持续加载。

拥有此标签的区块会使维度计算保持活跃。

; 未知标签
当系统需要立刻使用区块的数据，而区块还没有创建或生成到指定阶段时，系统自动给这个区块放置加载标签而不放置计算标签，它的存活时间为{{convert|1}}。未知加载标签的基础等级不固定，但都大于32，它的加载等级代表了它要求区块生成到什么阶段。这种情况会发生于各种游戏计算中，例如生物AI计算，生物生成等。

==== 等级传播 ====
带有加载标签的区块会向相邻的区块传播等级。对于每个标签，等级从带标签的区块位置开始传播，每向外传播一次就等级增加1。对于加载标签，等级只会传播到45，更大等级的区块不在内存中；对于计算标签，如果已经传播到33级，再向外传播就不会继续增长，维持在33级。假设带有标签的区块位置为''s''，基础等级为''l''，需要计算等级的区块位置为''d''，则这个区块的等级为<math>l+\max\{|x_s-x_d|,|z_s-z_d|\}</math>（不考虑已达到最大等级的状况），即本区块的等级等于标签的基础等级与本区块到标签区块的[[切比雪夫距离]]之和。

若一个区块传播获得了不同的等级，则最小的等级作为本区块的等级。如果一个带有标签的区块的基础等级大于其他区块传播而来的等级，那么等效于这个标签没有起到任何作用。

==== 闲置超时 ====
若一个维度长时间内没有玩家或实体出入，则不必要长时间计算维度内的一些内容，这就是闲置超时的作用。闲置超时每刻增加1，当维度内存在任何玩家或有使用{{cmd|forceload}}强制加载的区块时，闲置超时被禁用且被重置为0；当有实体进入或离开维度时，闲置超时也被重置为0。当值超过300时（15秒），这个维度就不会计算末影龙战斗、实体和方块实体，但仍会计算计划刻、[[世界边界]]、[[天气]]、[[袭击]]和普通方块事件，[[生成]]也会被计算，但由于维度内不存在玩家所以会失败。

随卸载过期的标签类型不会重置闲置超时。

==== 特殊情况 ====
一个区块中的事件可能会影响外部的区块。若外部的区块处于非活动状态，则在大多数情况下会立即暂停。但下面情况是一些例外：
* 已加载区块边缘的方块发生变化，可以将方块更新传播到非活动区块内的方块，并使它们做出适当的响应。
* 部分方块的行为使其可更新非活动区块中与活动区块毗邻的方块（后续称为“加载毗邻”），然后会因为该区块未加载而暂停，区块被加载后会恢复正常。譬如：
** 流动的水或熔岩、火、草和菌丝体可传播到加载毗邻，然后因上述原因停止传播。
*** 火的传播可见，但其动画不会被播放。
*** 草和菌丝体的传播，受影响的方块在其区块被加载前不会真正改变其外观，区块加载后会即刻改变。
** 南瓜茎可将其果实放置在加载毗邻上。

* 尝试移动到非活动区块的实体（如生物、矿车和箭）在离开加载区块后会即刻停止所有活动。它仍然可见但无法移动。当该区块被加载时，实体会继续移动。
* 点燃的TNT可以摧毁未加载区块内的方块，且与上述的其他事件不同，'''其效果不限于相邻的方块'''。附属效果等待该区块被加载才会生效。如：若爆炸破坏了非活动区块中支撑沙子或沙砾的方块，则沙子或沙砾不会立即掉落。摧毁某个方块的附着的情况相同，例如物品展示框和红石火把，它们在区块加载前不会掉落。
* 点燃的TNT被发射到未加载的区块时会暂停在外部空中的第一个方块。直到外部区块被加载，它才将恢复其飞行和倒计时。

{{main|红石电路#基本概念#红石系统}}
* 当区块被加载，当中的红石元件会加入链接图中。当区块被卸载，这些已在图中的红石元件不会被移出图，仍然会被正确计算信号（但对于消费者类元件，其无法响应信号改变并对世界造成影响）。因此：红石粉、红石中继器、红石比较器、红石火把支持抗卸载运行，只要它们被加载过（加入图）。

== 史莱姆区块 ==
{{Main|史莱姆#生成}}
史莱姆区块指的是一些在Y=40以下能够忽略亮度生成史莱姆的区块。这些区块在其他方面与所有其他区块相同。

=== Java版 ===
史莱姆区块在世界各地都存在（蘑菇岛除外）。有十分之一的区块都是史莱姆区块。这些史莱姆区块是通过将它们的区块坐标与世界种子相结合，通过伪随机算法确定的：
<syntaxhighlight lang="java">
Random rnd = new Random(
    seed +
    (int) (xPosition * xPosition * 0x4c1906) +
    (int) (xPosition * 0x5ac0db) + 
    (int) (zPosition * zPosition) * 0x4307a7L +
    (int) (zPosition * 0x5f24f) ^ 0x3ad8025f
);
return rnd.nextInt(10) == 0;
</syntaxhighlight>

即使用区块坐标和世界种子来生成介于0和9之间（含0和9）的随机整数，若该数字为0，则该区块是史莱姆区块。请注意，{{cd|xPosition}}和{{cd|zPosition}}是32位整数（INT）。

=== 基岩版 ===
基岩版中的史莱姆区块算法与Java版中的算法不同。该算法不依赖于世界种子，因此，每个世界中的史莱姆区块位置固定。<ref>@protolambda和@jocopa3进行过基岩版史莱姆区块算法的反向工程，可以在GitHub上找到：[https://github.com/depressed-pho/slime-finder-pe][https://gist.github.com/protolambda/00b85bf34a75fd8176342b1ad28bfccc]</ref><ref>Blocktopograph中的算法：[https://github.com/oO0oO0oO0o0o00/blocktopograph/tree/master/app/src/main/java/com/mithrilmania/blocktopograph/map/renderer/SlimeChunkRenderer.java SlimeChunkRenderer->isSlimeChunk(int chunkX, int chunkY)]</ref>

== 你知道吗 ==
* {{in|je}}一个世界中的一个维度可生成14,063,490,017,424（约14万亿）个真区块。
* 如果玩家位于未生成的区块里，世界会立即隐藏，直到玩家位于一个有效区块里。如果玩家的Y坐标在区块边界外时，这就不会被触发。
* {{in|be}}若区块中有一个子区块没有任何方块，则在其中放置方块后会触发区块加载动画。该漏洞{{Citation needed}}使放置的方块变成玩家视野方向天空的颜色大约1秒钟，然后逐渐变为正常的方块纹理。时间为日出或日落时，若玩家不断上下摆动头部，放置的这个方块会持续改变颜色1秒钟。这个方块也会让后面的方块不可见。
