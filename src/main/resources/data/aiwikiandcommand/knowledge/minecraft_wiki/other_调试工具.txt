'''调试工具'''，或'''调试功能（Debug Feature）'''<ref name="25w37a">{{snap|25w37a|Sep 09, 2025}}</ref>，是对游戏进行调试的高级功能。

== 使用 ==
调试工具旨在为高级玩家或开发人员提供更加详细的游戏运行信息。其不会在一般的游戏流程中启用，故拥有潜藏的崩溃风险，官方也不会发布调试工具的更新通知。<ref name="25w37a"/>

调试工具可以依赖系统属性来启用，这些系统属性在游戏内部也被称为'''调试属性（Debug Property）'''。在所有调试属性中，下列两个调试属性不用于调试的具体功能：

* <code>MC_DEBUG_ENABLED</code>：是否启用调试工具。
* <code>MC_DEBUG_PRINT_PROPERTIES</code>：若指定，则在游戏日志输出所有调试工具系统属性，每项系统属性的格式为<code>-{}-Debug property available: <''调试属性''>: <''数据类型''></code>

向游戏的JVM参数传入这些调试属性后即可启用调试工具。即若需启动调试工具，则需要下列命令：
{{syntaxhighlight|lang=bash|<nowiki>
java -DMC_DEBUG_ENABLED -D<调试属性>=<值> ... -cp client.jar <启动主类> ... # 客户端核心文件运行方式
java -DMC_DEBUG_ENABLED -D<调试属性>=<值> ... -DbundlerMainClass=<启动主类> -jar server.jar ... # 服务端核心文件运行方式
</nowiki>}}

所有的属性名称均以<code>MC_DEBUG_</code>作前缀，例如上文的<code>MC_DEBUG_ENABLED</code>和<code>MC_DEBUG_PRINT_PROPERTIES</code>。下文中，所有的调试属性均省略此前缀，例如章节[[#OPEN_INCOMPATIBLE_WORLDS|OPEN_INCOMPATIBLE_WORLDS]]对应的调试属性就是<code>MC_DEBUG_OPEN_INCOMPATIBLE_WORLDS</code>。

由于Minecraft分为了[[Java版网络协议#逻辑端|逻辑客户端和逻辑服务端]]，因而调试属性部分作用于客户端，部分作用于服务端。在正常的游戏流程下服务端的部分数据是不会同步到客户端的，而'''调试订阅（Debug Subscription）'''负责了客户端如何获取这些数据，只有符合要求的玩家才会发送并接收调试订阅。存档在单人游戏世界中运行时，玩家只在存档开启“允许命令”时才可获取调试信息；存档在独立服务器中运行时，玩家必须是服务器管理员才可获取调试信息。

=== 布尔属性 ===
这些调试属性的取值均为布尔值。
==== OPEN_INCOMPATIBLE_WORLDS ====
{{#var:ALL_SIDE}}
是否总是认为存档之间可以互相兼容，不检查存档的[[版本信息文件格式|开发分支]]。

在客户端启用时，世界选择屏幕中的所有存档均可直接打开，包括不兼容的存档。在服务端启用时，服务端可以直接加载不兼容的存档而不会拒绝加载。

==== ALLOW_LOW_SIM_DISTANCE ====
{{#var:CLIENT_SIDE}}
[[选项]]中“{{tp|options.simulationDistance}}”允许的最小值是否是2而不是5。

==== HOTKEYS ====
{{#var:CLIENT_SIDE}}
是否启用部分[[调试组合键]]。如果有任何冲突，此调试工具的调试组合键的优先级高于除{{key|F3+C}}外的任何调试组合键。<ref>{{bug|MC-301999}}</ref>

* {{key|F3+E}}：打开或关闭'''[[子区块]]路径（SectionPath）'''的渲染。与[[调试屏幕]]的<code>chunk_section_paths</code>作用相同。
* {{key|F3+F}}：打开或关闭'''[[迷雾]]（Fog）'''的渲染。
* {{key|F3+L}}：打开或关闭'''SmartCull'''。SmartCull是一种对视锥内可见区块选择编译的优化算法，仅在客户端非旁观模式下生效。
* {{key|F3+O}}：打开或关闭'''子区块八叉树（Frustum culling Octree）'''的渲染。与调试屏幕的<code>chunk_section_octree</code>作用相同。
* {{key|F3+U}}：打开'''视锥体（Frustum）'''的渲染。将以当前摄像机渲染一个视锥体，并停止正常游戏流程的渲染。
** {{key|F3+Shift+U}}：关闭视锥体的渲染，并恢复正常游戏流程的渲染。
* {{key|F3+V}}：打开或关闭'''子区块可视化（SectionVisibility）'''。与调试屏幕的<code>chunk_section_visibility</code>作用相同。
* {{key|F3+W}}：打开或关闭'''线条边框（WireFrame）'''。方块将只渲染边框，其余部分透明渲染。

==== UI_NARRATION ====
{{#var:CLIENT_SIDE}}
是否在各类屏幕中启用{{tr|复述功能|朗讀功能}}。忽略选项“{{tp|options.narrator}}”的设置。

==== SHUFFLE_UI_RENDERING_ORDER ====
{{#var:CLIENT_SIDE}}
是否打乱同一层级UI元素的渲染顺序。默认情况下，游戏以指定的渲染顺序逐一渲染各个UI元素，但如果开启此调试工具，在UI每次渲染时同一层级内的UI元素渲染顺序都将被打乱。此工具可以用于检查UI渲染时是否有隐藏的错误覆盖情况。

==== SHUFFLE_MODELS ====
{{#var:CLIENT_SIDE}}
是否打乱所有烘焙模型的非半透明渲染面的渲染顺序。与UI渲染类似，游戏以固定顺序渲染烘焙模型的各个面，启用此调试工具后各个面的渲染顺序被打乱。在正常情况下，打乱此渲染顺序不应该影响最终渲染效果，因为深度测试和透明测试不依托于渲染顺序，而是以深度和是否被透明剔除计算最终渲染效果。

==== RENDER_UI_LAYERING_RECTANGLES ====
<div style="float:right">{{filetr|Debug Feature debug render ui layering rectangles.png|thumb|300px|渲染区域调试}}</div>
{{#var:CLIENT_SIDE}}
是否在各种用户界面元素上渲染颜色为{{color|#4444FF77}}的矩形，此矩形通常代表此元素的渲染区域。

所有的界面背景、界面文字、界面图片、界面叠加元素均在此列，若有重合元素则叠加渲染。
{{-}}

==== PATHFINDING ====
[[File:Debug Feature debug pathfinding.png|thumb|300px|生物寻路调试]]
{{#var:CLIENT_SIDE}}
是否启用生物寻路系统的调试渲染，客户端将向服务端要求获取生物的寻路信息。

游戏只会渲染距离生物曼哈顿距离小于80格内的节点。生物寻路确定后，以绿色方块（{{color|#00FF0080}}）标记寻路终点，蓝色方块（{{color|#0000FF80}}）标记寻路经过节点位置，红色方块（{{color|#FF000080}}）标记生物将要走到的下一个寻路节点位置。同时以一条饱和度为90%，明度为90%的彩色的线沿寻路经过的节点位置连接生物与寻路终点，生物的一端为红色，终点一端为绿色。在生物周围，游戏也会以浅红色（{{color|#FFCCCC80}}）小方块代表寻路算法（A*）已遍历的节点，以浅蓝色（{{color|#CCFFFF80}}）小方块代表寻路算法中已经提交准备遍历但未进行遍历的节点。

游戏会在蓝色方块（寻路经过节点位置）上提供路径节点类型及其寻路代价。
{{-}}

==== SHOW_LOCAL_SERVER_ENTITY_HIT_BOXES ====
{{#var:CLIENT_SIDE}}
[[File:Debug Feature debug show local server entity hit boxes.png|thumb|300px|速度渲染调试]]
是否启用集成服务端速度的调试渲染。

此调试功能仍然需要显示实体判定箱后才渲染，游戏将以绿色碰撞箱指示已启用此调试工具，以黄色箭头指示位移变化量（DeltaMovement，存档数据{{nbt|list|Motion}}）。

此调试工具只对集成服务端内的实体生效，对于专用服务端或无法从集成服务端获取的实体，则仅渲染一个红色的“Missing Server Entity”。
{{-}}

==== SHAPES ====
{{#var:CLIENT_SIDE}}
是否启用方块形状的调试渲染。

当十字准星指向方块时，轮廓箱渲染为白色，碰撞箱渲染为黑色，遮挡形状渲染为黄色，互动箱渲染为蓝色。除轮廓箱外所有颜色的透明度均为40%，重叠部分混合渲染。

如果开启了选项“{{tp|options.accessibility.high_contrast_block_outline}}”，则渲染的线条会更粗。

==== NEIGHBORSUPDATE ====
[[File:Debug Feature debug neighborsupdate.png|thumb|300px|方块更新调试]]
{{#var:CLIENT_SIDE}}
是否启用[[方块更新]]的调试渲染，客户端将向服务端要求获取方块更新信息。

游戏将根据指定位置上最后一次更新的时间渲染一个白色的小方块，从开始渲染到消失一共{{convert|200}}，如果在这段时间内再次接收更新则重新计时。同时，游戏会渲染未消失前此位置接收到的所有更新数量。

此调试工具不区分PP更新和NC更新，仅计算有方块更新的数量。
{{-}}

==== EXPERIMENTAL_REDSTONEWIRE_UPDATE_ORDER ====
{{FakeImage|{{Animate|Debug Feature debug experimental redstonewire update order.png; Debug Feature debug experimental redstonewire update order off.png|300px}}|红石线更新顺序调试}}
{{Experimental|redstone_experiments|section=1|je=1}}
{{#var:CLIENT_SIDE}}
是否启用红石线更新顺序的调试渲染，客户端将向服务端要求获取红石线更新信息。

游戏会在红石线上渲染类似于调试准星的方向线条。蓝线为红石线更新的方向，红线固定指向上方，黄线指向红石线更新方向俯视视角下的逆时针90度方向。

方向线条只在红石线更新时才渲染。
{{-}}

==== STRUCTURES ====
[[File:Debug Feature debug structures.png|thumb|300px|结构片段调试]]
{{#var:CLIENT_SIDE}}
是否启用[[结构片段]]的调试渲染，客户端将向服务端要求获取结构及结构片段信息。

整个结构以白色边框标记，结构片段以蓝色边框标记，结构起始点的结构片段以黄色边框标记。
{{-}}

==== GAME_EVENT_LISTENERS ====
[[File:Debug Feature debug game event listeners.png|thumb|300px|游戏事件调试]]
{{#var:CLIENT_SIDE}}
是否启用[[游戏事件]]监听的调试渲染，客户端将向服务端要求获取游戏事件信息。

游戏会以透明度为35%的黄色方块标记振动接收者，所有振动接收者周围渲染以其为中心、接收半径为边长的黄色立方体表示接收范围，并在其上方渲染接收位置。同时，以透明度为20%的白色方块标记振动源，并指示产生此次振动的游戏事件。所有游戏事件发生{{convert|60}}后停止渲染。
{{-}}

==== DUMP_TEXTURE_ATLAS ====
{{#var:CLIENT_SIDE}}
是否每次构建[[纹理图集]]时生成纹理图集数据。与{{key|F3+S}}不同，游戏不会输出调试文本以供玩家点击文件链接直接打开生成结果。

==== STRUCTURE_EDIT_MODE ====
[[File:Debug_Feature_debug_structure_edit_mode.png|thumb|300px|结构编辑模式]]
{{#var:CLIENT_SIDE}}
当启用此项时，从[[结构模板]]放置的方块结构（使用[[结构方块]]加载的），会额外在其东、南、顶面放置一层[[结构空位]]，且放置结构空位时不产生NC更新。

同时，[[结构模板]]放置时（使用[[结构方块]]加载的、世界生成时放置的），不再自动填充可生成战利品容器的{{nbt|long|LootTableSeed}}。

==== SAVE_STRUCTURES_AS_SNBT ====
{{#var:CLIENT_SIDE}}
[[结构方块]]和[[测试实例方块]]是否以SNBT文件保存[[结构模板]]。

不影响通过其他方式保存的结构模板。结构模板任何的加载行为仍然需要NBT文件，而不能使用SNBT文件加载。

==== SYNCHRONOUS_GL_LOGS ====
{{#var:CLIENT_SIDE}}
是否以同步模式输出OpenGL调试日志。

默认情况下游戏以异步模式获取调试日志，这种方式不能保证日志输出顺序与实际发生的顺序一致。<ref>https://www.khronos.org/opengl/wiki/Debug_Output#Getting_messages</ref>启用同步模式后，游戏保证以事件发生的顺序输出对应的调试日志，以方便进行调试。

==== VERBOSE_SERVER_EVENTS ====
{{#var:SERVER_SIDE}}
是否在游戏日志中输出部分服务端事件。

游戏会输出下列信息：
* 区块任务（世界生成，光照计算）优先级变化：<code>-{}-RES <''区块位置''> <''原始优先级''> -> <''变化后优先级''></code>。
* 区块任务（世界生成，光照计算）提交：<code>-{}-SUB <''区块位置''> <''原始优先级''> <''任务执行器信息''> <''任务队列信息''></code>。
* 区块更新：<code>-{}-DMU <''要更新的区块数量''></code>。
* 区块光照初始化：<code>-{}-LIT <''区块位置''></code>。
* 向玩家发送区块数据：<code>-{}-SEN <''区块位置''></code>。
* 区块添加加载或计算标签：<code>-{}-ATI <''区块位置''> <''标签信息''></code>。
* 区块移除加载或计算标签：<code>-{}-RTI <''区块位置''> <''标签信息''></code>。

由于输出消息以调试等级（DEBUG）日志输出，且原版游戏中Log4j2配置日志等级输出为信息（INFO），导致此调试属性对原版游戏没有任何作用。如果需要查看此调试信息，则必须修改<code>log4j2.xml</code>以允许调试级别日志输出。

==== NAMED_RUNNABLES ====
{{#var:SERVER_SIDE}}
是否为任务信息添加调试名称，但正常的游戏流程及日志输出几乎不可能见到这些名称。这些任务基本都为区块光照计算任务。

==== GOAL_SELECTOR ====
[[File:Debug Feature debug goal selector.png|thumb|300px|意向系统AI调试]]
{{#var:CLIENT_SIDE}}
是否启用意向系统[[生物AI]]的调试渲染，客户端将向服务端要求获取生物AI意向系统数据。

游戏只会渲染以<code>-{}-(''摄像机X坐标'', 0, ''摄像机Z坐标'')</code>为中心，欧几里得距离小于160格内生物的意向系统数据。

如示例图的苦力怕，目前生效的意向为随机视角意向（''Random Look Around Goal''）。
{{-}}

==== VILLAGE_SECTIONS ====
[[File:Debug Feature debug village sections.png|thumb|300px|村庄区域调试]]
{{#var:CLIENT_SIDE}}
是否启用村庄区域的调试渲染，客户端将向服务端要求获取有效的村庄范围数据。

村庄范围是以已绑定的工作方块的子区块为中心，范围为3×3×3子区块的空间，游戏将以{{color|#33FF3326}}的立方体渲染这些位置。
{{-}}

==== BRAIN ====
[[File:Debug Feature debug brain.png|thumb|300px|生物记忆调试]]
{{#var:CLIENT_SIDE}}
是否启用[[生物AI#记忆行为系统|记忆行为系统]]生物AI的调试渲染，客户端将向服务端要求获取这些数据。

游戏只会渲染最近指向的生物的详细AI数据，且不会渲染距离玩家欧几里得距离大于30的生物的AI数据。如果玩家为旁观模式，则只会渲染非详细AI数据。详细的AI数据包括：
* 生物名称。
** 如果生物没有自定义名称，则根据下列列表，以UUID为随机数发生器种子，挑选姓和名组成一个名称：
*** 姓包括：{{cd|Fox|Tail|Jaw|Whisper|Twig|Root|Finder|Nose|Brow|Blade|Fry|Seek|Wart|Tooth|Foot|Leaf|Stone|Fall|Face|Tongue|Voice|Lip|Mouth|Snail|Toe|Ear|Hair|Beard|Shirt|Fist|d=pretty}}。
*** 名包括：{{cd|Slim|Far|River|Silly|Fat|Thin|Fish|Bat|Dark|Oak|Sly|Bush|Zen|Bark|Cry|Slack|Soup|Grim|Hook|Dirt|Mud|Sad|Hard|Crook|Sneak|Stink|Weird|Fire|Soot|Soft|Rough|Cling|Scar|d=pretty}}。
** 例如示例图中，村民没有自定义名称，根据其UUID随机选中了<code>Fire</code>为姓，<code>Mouth</code>为名，组成<code>FireMouth</code>作为生物名称。
* 村民职业及当前经验。
* 生物当前生命值与最大生命值。
* 生物物品栏信息，生物没有物品栏时不显示此项。
* 生物当前正在运行的行为。
* 生物当前激活的活动。
* 村民是否有生成铁傀儡的意愿。
* 监守者的愤怒等级，生物不是监守者时不显示此项。
* 村民言论及其数值。
* 生物当前拥有的记忆及其数值，如果字符串过长则截断为255字符。

对于非详细的AI数据，游戏只会渲染生物名称和是否有生成铁傀儡的意愿。

{{-}}

==== POI ====
[[File:Debug Feature debug poi.png|thumb|300px|兴趣点调试]]
{{#var:CLIENT_SIDE}}
是否启用[[兴趣点]]（POI）的调试渲染，客户端将向服务端要求获取兴趣点数据。

游戏只会渲染摄像机周围欧几里得距离小于30的兴趣点信息，在兴趣点位置上渲染兴趣点类型和兴趣点的认领数量。

如果启用了<code>BRAIN</code>，则还会显示用于村庄的兴趣点的认领情况、认领者和可能认领者，且兴趣点不存在但村民的记忆未丢失此兴趣点时渲染为“幽灵兴趣点”（Ghost POI）。
{{-}}

==== BEES ====
{{Filetr|Debug Feature debug bees.png|thumb|300px|蜜蜂信息调试}}
{{#var:CLIENT_SIDE}}

==== BLOCK_BREAK ====
{{#var:ALL_SIDE}}
是否在游戏日志中输出方块的[[挖掘]]信息。

游戏可以输出下列信息，这些信息代表挖掘的不同流程，详细可见{{slink|挖掘|挖掘流程}}：
* <code>-{}-Start break <''坐标''> <''方块''></code>：（客户端）开始破坏方块。
* <code>-{}-Stop dest <''坐标''> <''方块''></code>：（客户端）停止破坏方块。
* <code>-{}-Finished breaking <''坐标''> <''挖掘前方块''> -> <''挖掘后方块''></code>：（客户端）挖掘方块完毕，挖掘动作停止。
* <code>-{}-Client broke <''坐标''> <''挖掘前方块''> -> <''挖掘后方块''></code>：（客户端）预测破坏方块完毕。（此消息以错误等级日志输出）
* <code>-{}-Abort old break <''坐标''> <''挖掘前方块''> -> <''挖掘后方块''></code>：（客户端）在挖掘进行期间改变挖掘目标而中止上一次挖掘，并同时开始当前挖掘目标的挖掘。
* <code>-{}-Creative start <''坐标''> <''方块''></code>：（客户端）创造模式下立刻预测破坏方块。
* <code>-{}-Creative cont <''坐标''> <''挖掘前方块''> -> <''挖掘后方块''></code>（客户端）创造模式下持续挖掘，添加挖掘冷却。
* <code>-{}-Server broke <''坐标''> <''挖掘前方块''> -> <''挖掘后方块''></code>：（服务端）确认破坏方块，进行方块移除等实际行为。

所有坐标的格式为<code>-{}-BlockPos{x=<''x坐标''>, y=<''y坐标''>, z=<''z坐标''>}</code>；所有方块的格式为<code>-{}-Block{<''方块ID''>}[<''方块属性''>=<''值''>]</code>，且方块属性可能不存在。

游戏日志也会尝试以调试等级日志输出部分信息，但原版游戏默认不输出调试等级日志，因而下列信息不会显示：
* （客户端）<code>-{}-ACK <''玩家破坏方块{{tr|数据包|封包}}的预测序号''></code>
* （服务端）<code>-{}-Server ACK <''方向''> <''是否为有效破坏行为''> <''玩家破坏方块{{tr|数据包|封包}}的预测序号''> <''调试信息''></code>

==== SHOW_SERVER_DEBUG_VALUES ====
{{#var:CLIENT_SIDE}}
是否在调试屏幕上显示部分服务端信息，包括：

* 服务端的生物群系。（<code>biome</code>）
* 服务端的光照。（<code>light_levels</code>）
* 当前摄像机指向方块位置的服务端方块数据。（<code>looking_at_block</code>）
* 当前摄像机指向流体位置的服务端流体数据。（<code>looking_at_fluid</code>）

此调试工具仅能在集成服务端上生效，专用服务端无法获取数据将不会显示相应的服务端信息。

==== FEATURE_COUNT ====
{{#var:CLIENT_SIDE}}
是否记录地物放置信息。

游戏会添加两个调试组合键：
* {{key|F3+R}}：重置当前已记录的地物放置信息和放置地物区块的数量。
* {{key|F3+L}}：在日志输出放置地物区块的数量和地物放置的信息。

如果5分钟内没有产生任何地物放置，游戏会自动重置已记录的地物放置信息和放置地物区块的数量。

由于游戏输出此消息以调试等级输出，且原版游戏默认不输出调试等级日志，这些信息默认不可见。当输出时，游戏按照每个维度输出：
* 在此维度进行地物放置的区块数量：<code>-{}-<running|dead> <''维度''> total_chunks: <''区块数量''></code>。
* 接下来每一行都是在此维度放置的地物信息：<code>-{}-<running|dead> <''维度''> <''放置数量''> <''每区块平均放置数量''> <''放置位置''> <''地物类型''> <''地物信息''></code>。

==== CALCULATE_SOLID ====
{{#var:ALL_SIDE}}
{{added in development|jev=26.3|section=1}}
是否报告方块固体方块（<code>legacySolid</code>）属性，以及潜在的多重定义。

游戏会在注册方块时记录每个方块的固体方块属性，并以调试日志等级输出<code>-{}-The following blocks are <''是否是固体方块''> because: <''原因''>:\n <''方块注册名''></code>。如果同一个方块拥有多种固体方块属性，则额外以调试日志等级输出<code>-{}-Block <''方块注册名''> has multiple values for solid. Existing: <''（旧）是否是固体方块''> (<''旧原因''>) New: <''（新）是否是固体方块''> (<''新原因''>)</code>

可能的取值如下：

{|class="wikitable"
! 是否是固体方块 !! 原因
|-
| true || orceSolidOn called on properties
|-
| true || collision shape bounds size is large enough
|-
| true || collision shape bounds are higher than 1
|-
| false || forceSolidOff called on properties
|-
| false || cache is null
|-
| false || collision shape is empty
|-
| false || fallthrough
|}

==== FORCE_TELEMETRY ====
{{#var:CLIENT_SIDE}}
在[[wzh:集成开发环境|IDE]]中是否记录遥测数据。对原版游戏没有任何作用。

==== DONT_SEND_TELEMETRY_TO_BACKEND ====
{{#var:CLIENT_SIDE}}
在IDE中是否禁止遥测数据发送。对原版游戏没有任何作用。

=== 数值属性 ===
这些调试属性的取值均为整型数值。

==== FAKE_LATENCY_MS ====
{{#var:CLIENT_SIDE}}
设置对集成服务端的模拟延迟毫秒数，默认为0。

==== FAKE_JITTER_MS ====
{{#var:CLIENT_SIDE}}
设置对集成服务端的模拟抖动毫秒数，默认为0。

仅在<code>FAKE_LATENCY_MS</code>大于0时才有实际作用。此随机抖动直接与基础的延迟毫秒数相加得到最终的延迟时间。

{{#var:CLIENT_SIDE}}
是否启用[[高度图]]的调试渲染。被调试渲染器<code>visualize_height_map</code>取代。

==== COLLISION ====
{{#var:CLIENT_SIDE}}
是否启用方块[[碰撞箱]]的调试渲染。被调试渲染器<code>visualize_collision_boxes</code>取代。

==== LIGHT ====
[[File:Debug Feature debug light.png|thumb|300px]]
{{#var:CLIENT_SIDE}}
是否显示天空光的信息。

游戏将此信息分为两部分渲染：
* 子区块光照状态：子区块未计算天空光照时为<code>2</code>，计算天空光照且子区块内全部为空气且天空光均为15时为<code>1</code>，无天空光照计算时为<code>n/a</code>，其他条件下为<code>0</code>。
* 方块天空光状态：如果方块位置上的天空光不为15，则在对应位置上渲染天空光数值。由于一些原因，游戏并不会渲染此信息。

游戏只会渲染摄像机周围切比雪夫距离小于10的方块和子区块的天空光信息。
{{-}}

==== SKY_LIGHT_SECTIONS ====

==== SHOW_LOCAL_SERVER_ENTITY_HIT_BOXES（1.21.11前） ====
[[File:Debug Feature debug show local server entity hit boxes Revision 1.png|thumb|300px]]
{{#var:CLIENT_SIDE}}
是否启用集成服务端[[判定箱]]和速度的调试渲染。

此调试功能仍然需要显示实体判定箱后才渲染，服务端判定箱以绿色渲染，客户端保持白色，服务端速度则渲染为一条蓝色的线。

此调试功能只能对集成服务端内的实体生效，对于专用服务端所有实体都将在上方渲染一个颜色为黄色的<code>Missing</code>，且不渲染服务端判定箱。

此渲染每100毫秒更新一次。
{{-}}

{{#var:CLIENT_SIDE}}

==== DUMP_INTERPOLATED_TEXTURE_FRAMES ====
{{#var:CLIENT_SIDE}}
是否生成带插值（{{nbt|boolean|animation.interpolate}}）的动态纹理。对于纹理<code>-{}-<''命名空间''>:<''ID''></code>而言，其生成的纹理位于{{filepath|screenshots/debug/<''命名空间''>_<''ID''>/<''命名空间''>_<''ID''>_<''n''>_<''起始帧编号''>_<''目标帧编号''>.png}}，其中<code>''n''</code>的取值为0至{{tp|options.mipmapLevels}}，{{tp|options.mipmapLevels}}为关时视为0。

游戏每次更新动态纹理时都会进行导出，因此游戏会不停尝试导出插值纹理。

==== NATIVE_WEBRTC_LOGS ====
{{#var:CLIENT_SIDE}}
是否在p2p连接时，将WebRTC的日志输出到游戏日志中。
